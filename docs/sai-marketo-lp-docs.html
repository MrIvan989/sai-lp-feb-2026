SAI Landing Page Template
Documentation

Marketo Guided Landing Page templates for the SAFe Summit Rewind webinar series.

Two active templates: SAFe-safe-rewind-simplified.html (SAFe brand, Noto Sans font) and AIN-safe-rewind-simplified.html (AI-Native brand, Montserrat font). They share the same section structure but use different branding, CSS tokens, and variable prefixes. Toggle brands using the sidebar buttons.

Repository Overview

This repository contains Marketo Guided Landing Page templates for lead-generation webinars. The templates are designed for use inside Marketo's template editor — all configurable elements are exposed through <meta> tags that power the Marketo UI.

Architecture

Marketo Meta Variable System

Every configurable property is declared via <meta> tags in the <head>. These tags define the Marketo editor UI fields. The HTML body and CSS reference these variables using ${variable-id} tokens — Marketo replaces them at compile time.

Five Marketo variable types are used:

TypeCSS ClassPurposeExample
mktoBooleanclass="mktoBoolean"Show/hide toggles. Defines two possible output values.true_value="block" false_value="none"
mktoStringclass="mktoString"Free-text values (URLs, order numbers, button labels).default="Save My Seat"
mktoColorclass="mktoColor"Color picker for backgrounds, text, accents.default="#FFFBF4"
mktoText<div class="mktoText">Rich text editable regions in the page body.mktoname="Hero Light Content"
mktoImg<div class="mktoImg">Image picker for logos, banners, speaker photos.mktoname="Header Logo"
SAFe has ~113 meta variables; AIN has ~117. The difference comes from AIN-specific variables like form-title-color, form-bgColor, and quotes-color that SAFe handles differently.

Section Ordering System

Every section has an order-* mktoString variable. The body uses a flexbox wrapper (.page-wrapper { display: flex; flex-direction: column; }) and each section's CSS uses order: ${order-*}. This enables drag-and-drop section reordering in Marketo's editor without touching HTML structure.

Visibility Toggles

Each section has a show-* mktoBoolean that outputs "block" or "none". CSS applies it directly:

/* SAFe example */
.sec1-hero {
  display: ${show-hero-light};
  order: ${order-hero-light};
}
Takeaway items 5–10 use !important values. Because Bootstrap's .d-flex utility carries !important, the boolean outputs "flex!important" / "none!important". CSS selectors use combined specificity: .takeaway-item-5.d-flex { display: ${show-takeaway5}; }

parse-tokens.js / parse-tokens-ain.js

These files serve one purpose: make the templates render correctly when opened directly in a browser (outside of Marketo's compilation pipeline).

How It Works

  1. Both files define a tokenDefaults object mapping every CSS token variable to a fallback value.
  2. On DOMContentLoaded, each file scans all <style> blocks and replaces any remaining ${variable-name} tokens with the fallback values.
  3. If Marketo has already compiled the template (replacing ${...} with real values), the regex finds nothing and the script is a no-op.

What They Cover

The token defaults cover only CSS-referenced tokens — show/hide booleans, background colors, section background colors, footer text colors, etc. They do not cover mktoText or mktoImg content (which is hardcoded as defaults in the HTML body).

SAFe parse-tokens.js (73 lines)

const tokenDefaults = {
    // ── Page
    'bodyBGcolor':     'var(--sai-white)',
    // ── Header
    'show-header':     'block',
    'header-bgColor':  'var(--sai-cream)',
    'header-logo-position': '0 auto',
    // ── Hero Light
    'show-sec1':        'none',
    'hero-col-full-width': '58.333%',
    'sec1-bgColor':      'var(--sai-light-blue)',
    'show-event-card':   'block',
    'show-event-card-2': 'none',
    // ... covers all 12 sections + carousel
};

document.addEventListener('DOMContentLoaded', () => {
    document.querySelectorAll('style').forEach(styleEl => {
        styleEl.textContent = styleEl.textContent.replace(
            /\$\{([\w-]+)\}/g,
            (match, tokenName) => tokenDefaults[tokenName] ?? match
        );
    });
});

How-To: Add a New Section

Adding a new section requires changes in three places: HTML body, <head> meta variables, and the <style> block. Here's the full checklist:

1

Add Section HTML to the Body

Place your new <section> inside .page-wrapper, before the footer. Give it a unique class (e.g., my-new-section).

<section class="my-new-section mx-4 my-4 rounded-4">
  <div class="container">
    <div class="mktoText" id="my-section-content" mktoname="My Section Content">
      <h2>New Section Title</h2>
      <p>Your content here.</p>
    </div>
  </div>
</section>
2

Add CSS Rules in the <style> Block

Add rules for display, order, background-color, and optional background image. Follow the established pattern:

/* ===== SECTION - MY NEW SECTION ===== */
.my-new-section {
  display: ${show-my-section};
  order: ${order-my-section};
  background-color: ${my-section-bgColor};
  background-image: url('${my-section-bgImage}');
  background-size: cover;
  background-position: center center;
  padding: 60px 0;
}
3

Add Meta Variables in the <head>

Declare show/hide, order, and color variables. Place them with the other section variables:

<!-- ===== MY NEW SECTION VARIABLES ===== -->
<meta class="mktoBoolean" id="show-my-section" mktoname="Show My Section?"
      default="false" true_value="block" false_value="none"
      false_value_name="Hide" true_value_name="Show">
<meta class="mktoColor" mktoname="My Section BG Color" id="my-section-bgColor"
      default="#FFFBF4">
<meta class="mktoString" mktoname="My Section BG Image URL" id="my-section-bgImage"
      default="">
<meta class="mktoString" id="order-my-section" mktoname="My Section Order"
      default="13">
4

Update parse-tokens.js (both files)

Add token fallback values so the section previews correctly in a local browser:

const tokenDefaults = {
    // ... existing tokens ...
    'show-my-section':   'none',       // change to 'block' to preview
    'my-section-bgColor': 'var(--sai-cream)',
};
5

Add Responsive CSS (767px breakpoint)

Add .my-new-section to the mobile override block:

@media (max-width: 767px) {
  .my-new-section {
    margin-left: 0 !important;
    margin-right: 0 !important;
    border-radius: 0 !important;
    padding: 40px 0;
  }
}
Sync both templates. When you add a section to SAFe-safe-rewind-simplified.html, add the same section (with AIN-appropriate colors) to AIN-safe-rewind-simplified.html. Keep the HTML structure identical; only the default values and CSS tokens should differ.

How-To: Add a Text Module

A text module is a mktoText region — rich text editable by marketing teams in the Marketo editor. Adding one requires only the HTML body markup:

1

Place a mktoText div inside the target section

Use a unique id and a descriptive mktoname (this is what appears in Marketo's editor dropdown):

<div class="mktoText" id="sec-extra-disclaimer" mktoname="Extra Disclaimer Text">
  <p class="text-muted small">Default disclaimer text here.</p>
</div>
2

Style with existing CSS classes

No CSS changes needed for mktoText regions — they inherit the section's typography. Use Bootstrap utility classes (text-muted, small, text-center) for quick formatting.

No meta variables or parse-tokens changes needed. mktoText regions don't use CSS ${...} tokens — they render their content directly in the body.

How-To: Add a Speaker

Speakers 1–2 are always in the DOM. Speakers 3–5 follow the exact same pattern: mktoImg photo + mktoText bio, wrapped in a togglable column. To add a Speaker 6:

1

Add the column wrapper and card HTML

Clone the speaker 3–5 pattern with a new index:

<!-- Speaker 6 -->
<div class="col-md-3 col-sm-6 speaker-6-col">
  <div class="speaker-card rounded-4">
    <div class="mktoImg" id="sec4-speaker6-img" mktoname="Speaker 6 Photo">
      <img class="speaker-photo" src="...andrew-profile.png">
    </div>
    <div class="speaker-bio">
      <div class="mktoText" id="sec4-speaker6-info" mktoname="Speaker 6 Info">
        <h4>Speaker Name</h4>
        <p>Speaker Title</p>
      </div>
    </div>
  </div>
</div>
2

Add the CSS toggle rule

In the <style> block, next to the other speaker column rules:

.speaker-6-col { display: ${show-speaker-6}; }

Add the meta variable

In the <head>, with the other speaker toggles:

<meta class="mktoBoolean" id="show-speaker-6" mktoname="Show Speaker 6?"
      default="false" true_value="block" false_value="none"
      false_value_name="Hide" true_value_name="Show">
4

Update parse-tokens.js

Add to both parse-tokens.js and parse-tokens-ain.js:

'show-speaker-6': 'none',

How-To: Add an Image

Images use Marketo's mktoImg component — the editor provides an image picker, and the template supplies a default fallback. Two patterns exist in the codebase:

Pattern A: Inline mktoImg (Header, Banners, Speakers)

The image is part of a section's layout, wrapped in a <div class="mktoImg"> with a unique id:

<div class="mktoImg" id="my-image" mktoname="My Custom Image">
  <img src="https://placehold.co/400x200" alt="" class="my-custom-image-class">
</div>

Pattern B: mktoImg as a URL source (Carousel Cards)

For JS-driven content, the image is referenced as a Marketo token variable in the script:

const card = {
    image: "${card7-img}",  // Marketo replaces at compile time
    title: "${card7-title}",
};
No meta variables needed for Pattern A. The mktoImg class and mktoname attribute are self-declaring — Marketo's editor picks them up automatically. Pattern B requires corresponding <meta> declarations if you want the URL configurable in the editor.

How-To: Add Meta Variables

Meta variables power the Marketo editor UI. They come in five types; choose based on what the variable controls.

1

Choose the correct type and place <meta> tags in <head>

mktoBoolean (Show/Hide Toggle)

For toggling visibility. true_value and false_value are what get injected into ${id} tokens.

<meta class="mktoBoolean"
      id="show-my-feature"
      mktoname="Show My Feature?"
      default="false"
      true_value="block"
      false_value="none"
      false_value_name="Hide"
      true_value_name="Show">
If the element uses Bootstrap flex classes, your boolean values must include !important: use true_value="flex!important" false_value="none!important".

mktoString (Text / URL / Number)

For free-text values — button labels, URLs, section order numbers, image URLs.

<meta class="mktoString"
      id="my-button-text"
      mktoname="My Button Text"
      default="Click Here">

mktoColor (Color Picker)

For background colors, text colors, or accent colors. Use 6-digit hex defaults.

<meta class="mktoColor"
      id="my-bg-color"
      mktoname="My BG Color"
      default="#FFFBF4">
2

Reference the variable in CSS

Use ${id} syntax in the <style> block:

.my-feature {
  display: ${show-my-feature};
  background-color: ${my-bg-color};
}
3

Optionally reference in the HTML body

Tokens work in body markup too — useful for links, button text, and image sources:

<a href="${my-link-url}">${my-button-text}</a>
4

Update parse-tokens.js (CSS tokens only)

Only add CSS tokens (show/hide booleans, colors) — not body-text tokens:

'show-my-feature': 'none',
'my-bg-color':    'var(--sai-cream)',
